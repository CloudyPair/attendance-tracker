# ФЛАГ

Веб-журнал посещаемости студентов и Telegram-бот на общем ядре Django.
Python 3.13, Django 6.1, SQLite для локального запуска.

## Возможности

- Расписание группы по дням и неделям, импорт календаря из API МИЭТ или ICS.
- Отметка группы старостой, заместителем или временной заменой.
- Правки с обязательным объяснением, историей и защитой от устаревшей формы.
- Личная статистика, кабинет преподавателя, порог посещаемости и CSV/XLSX.
- Оспаривание пропуска с документом; решение преподавателя предмета.
- Временная замена старосты до 00:00 по московскому времени.
- Telegram: расписание, статистика, заявки, замены и уведомления.

## Локальный запуск

Из корня проекта на Windows в PowerShell:

```powershell
py -3.13 -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py seed_demo
.\venv\Scripts\python.exe manage.py createsuperuser
.\venv\Scripts\python.exe manage.py runserver
```

Существующий локальный `.env` сохраняйте при обновлении проекта.
Сайт: <http://127.0.0.1:8000/>. Администратор: <http://127.0.0.1:8000/admin/>.

На Linux:

```bash
python3.13 -m venv venv
source venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

## Конфигурация

Образец переменных — `.env.example`. Настоящие токены и ключи хранятся в
локальном `.env`, который исключен из Git.

| Переменная | Назначение |
|---|---|
| `DJANGO_DEBUG` | `true` для локальной разработки; `false` для серверного запуска |
| `DJANGO_SECRET_KEY` | Секретный ключ Django; для сервера нужен новый случайный ключ |
| `DJANGO_ALLOWED_HOSTS` | Допустимые имена хостов через запятую |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Доверенные адреса с протоколом через запятую, если нужны |
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `TELEGRAM_BOT_USERNAME` | Имя бота без `@` |
| `SITE_URL` | Адрес сайта для ссылок из Telegram |

Команда для создания нового ключа: `python -c "import secrets; print(secrets.token_urlsafe(64))"`.
При `DJANGO_DEBUG=false` приложение требует серверный ключ и включает secure cookies.
Серверная публикация также требует WSGI-сервера, HTTPS, настроенной раздачи
статики и резервного копирования. Конфигурация Docker/PostgreSQL для VPS
пока не включена в эту сборку.

## Демонстрационные данные

`seed_demo` создает ИВТ-31, 15 вымышленных студентов и одного преподавателя.
Пароль новых учебных аккаунтов — `1234`; существующие пароли сохраняются.
Администратор создается отдельно командой `createsuperuser`.

| Роль | Логин |
|---|---|
| Староста | `ivt31_01` |
| Заместитель | `ivt31_02` |
| Студенты | `ivt31_03` … `ivt31_15` |
| Преподаватель | `ivt31_teacher` |

Тестовый преподаватель закреплен за всеми предметами группы. Реальные ФИО
преподавателей в расписании остаются в исходных данных МИЭТ.

Календарь `data/ivt31.ics` содержит 300 реальных занятий осеннего семестра
2026/2027, полученных 23.11.2026. Источник и сведения о подготовке —
`data/ivt31_source.json`. При первичной подготовке использован
[MPSU/schedule_parser](https://github.com/MPSU/schedule_parser).

Для заполнения пустых прошлых отметок с посещаемостью 80–90%:

```powershell
.\venv\Scripts\python.exe manage.py fill_demo_attendance --through 2026-11-23
```

Команда сохраняет ручные правки, работает только с завершенными занятиями
и не добавляет причины. Повторный запуск не создает дубликатов.

## Работа с журналом

Администратор управляет группами, студентами, ролями и преподавателями.
В форме группы кнопка «Сохранить и загрузить расписание МИЭТ» получает
календарь по названию, например ИВТ-32. Преподавателю назначаются предметы
конкретных групп. Импорт разовый: заполненное расписание повторно не заменяется.

Отметка открыта с 00:00 дня занятия до 00:00 следующего дня по Москве.
Первая отметка сохраняется без причины, правка — с объяснением.
Временную замену назначает староста или заместитель до конца текущего дня.

Студент выбирает пропуск и отправляет одну заявку «Оспорить» с объяснением
и необязательным документом до 5 МБ. Преподаватель своего предмета скачивает
документ и исправляет отметку на «Был» либо отклоняет с комментарием.
Удаление спора из истории сохраняет отметку и историю ее изменений.
Вложения доступны только автору заявки и преподавателям предмета.

Ручной импорт из файла:

```powershell
.\venv\Scripts\python.exe manage.py import_schedule ИВТ-32 schedule.ics --semester "Осень 2026/2027"
```

## Telegram

Заполните переменные бота в `.env`. В отдельном терминале запустите:

```powershell
.\venv\Scripts\python.exe -X utf8 manage.py runbot
```

В личном кабинете студента откройте Telegram, получите одноразовую ссылку,
перейдите в бот и нажмите Start. Ссылка действует 15 минут; новая отменяет
предыдущую. Пароль в боте не вводится. Один чат привязывается к одному студенту.

Команды: `/menu`, `/today`, `/week`, `/attendance`, `/absences`,
`/disputes`, `/delegation`, `/cancel`, `/logout`.

Через «Оспорить» можно прислать текст либо документ/фото до 5 МБ с объяснением
в подписи. Решения принимает преподаватель на сайте. Выход удаляет привязку,
гасит ссылки входа и отменяет ожидающие уведомления.

Очередь уведомлений хранится в БД. Бот проверяет ее каждые 30 секунд и
повторяет неудачную доставку до пяти попыток, с интервалом не менее минуты.
Остановка бота не продлевает полномочия временной замены.
Запускайте один процесс бота на один токен. После изменения кода нужен перезапуск.

## Проверки

```powershell
.\venv\Scripts\python.exe manage.py check
.\venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\venv\Scripts\python.exe -m coverage run -m pytest -q
.\venv\Scripts\python.exe -m coverage report
.\venv\Scripts\python.exe -m coverage html
```

Тесты используют отдельную БД, временные вложения, управляемое время и
автономные адаптеры внешних сервисов. Они не меняют рабочую БД и не отправляют
реальные сообщения Telegram. Покрытие исключает тесты и миграции.

GitHub Actions повторяет проверки и сохраняет JUnit XML и отчет покрытия.
Фактический запуск Actions происходит после push или открытия pull request.

## Структура

- `attendance/models.py` — модели и операции предметной области.
- `attendance/services/` — права и общие сценарии сайта и бота.
- `attendance/views.py`, `student_views.py` — страницы Django.
- `attendance/telegram_bot.py` — клиент aiogram.
- `attendance/tests/` — модульные и приемочные проверки.
- `data/` — исходный календарь и сведения о его получении.
- `UML/` — исходники диаграмм и SVG.
- `scripts/` — вспомогательные утилиты.

Для обновления диаграмм укажите установленный PlantUML:
`./UML/generate-plantuml.ps1 -PlantUmlJar C:\tools\plantuml.jar`.

Рабочие БД, загруженные документы, секреты, окружение Python и отчеты
покрытия исключены из Git. После клонирования создайте `.env` и примените
миграции; данные и вложения переносятся отдельно.
