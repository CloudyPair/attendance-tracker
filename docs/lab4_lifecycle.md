# ЛР4. Модель жизненного цикла проекта
## 1. Модели жизненного цикла

| Модель | Суть |
|---|---|
| **Каскадная (водопадная)** | Этапы идут строго друг за другом: требования -> проектирование -> код -> тестирование -> внедрение. Возврата назад нет |
| **V-образная** | Каскад, где каждому этапу разработки соответствует свой этап проверки (требования - приёмочные испытания, архитектура - системное тестирование, модули - модульное) |
| **Прототипирование** | Быстро делают черновой прототип, уточняют по нему требования с заказчиком, затем пишут систему заново | 
| **Спиральная** | Разработка витками; на каждом витке - планирование, анализ рисков, разработка, оценка |
| **Итерационно-инкрементная** | Система собирается частями (инкрементами); каждая часть проходит мини-цикл (итерацию): требования -> проектирование -> код -> отладка. После каждой итерации есть работающая версия |
| **Гибкие** | Короткие спринты по 1–2 недели, роли (владелец продукта), ежедневные встречи, ретроспективы |

---

## 2. Выбранная модель: итерационно-инкрементная

**Почему она подходит проекту:**
- Основные требования известны из ТЗ. Дополнения,
  появившиеся после ЛР1 (импорт расписания `.ics`, порог с иконками, споры,
  Telegram-бот, замена старосты), добавляются отдельными инкрементами.
- После каждой итерации есть работающая версия

**Почему не подошли другие модели:**

| Модель | Причина отказа |
|---|---|
| Каскадная | Требования уже менялись |
| V-образная | Для учёта посещаемости избыточна |
| Прототипирование | Требования и так ясны; одноразовый прототип означает писать код дважды |
| Спиральная | Формальный анализ рисков на каждом витке избыточен для данного проекта |
| Гибкая | Слишком сложная иерархия для небольшой команды |
